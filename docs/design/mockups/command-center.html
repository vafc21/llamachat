I want to build a CLI tool in Rust that watches a directory and runs tests when files change. What's the best approach?
llama3.2:3b ~ 234ms

Use the notify crate. Here's the architecture:

src/main.rs 
use notify::{Watcher, RecursiveMode, watcher};
use std::process::Command;

fn main() {
    let (tx, rx) = std::sync::mpsc::channel();
    let mut watcher = watcher(tx, Duration::from_secs(1)).unwrap();
    watcher.watch("./src", RecursiveMode::Recursive).unwrap();
    
    for event in rx {
        Command::new("cargo").arg("test").status().unwrap();
    }
}

Key architecture decisions: debounce strategy (batch events within a time window), filter patterns to ignore noise (target/, .git/), and whether to run all tests or only affected ones via path matching.

Can I also make it watch config files and restart a dev server?
llama3.2:3b ~ 187ms

Yes — the cleanest pattern is a watch manifest with per-target config:

watch.yaml:

watch.yaml 
targets:
  tests:
    pattern: "src/**/*.rs"
    command: "cargo test"
    debounce: 500ms
  server:
    pattern: "config/**/*.yaml"
    command: "kill -HUP $(pgrep server)"
    debounce: 200ms

This is how cargo-watch and watchexec work — you'd be building a focused, single-purpose alternative. Great Rust learning project.
