I want to build a command-line tool in Rust that watches a directory and runs tests when files change. What's the best approach?
14:15:32

Great choice — you'll want the notify crate for filesystem events.

use notify::{Watcher, RecursiveMode, watcher};
use std::process::Command;

fn main() {
    let (tx, rx) = std::sync::mpsc::channel();
    let mut watcher = watcher(tx, Duration::from_secs(1)).unwrap();
    watcher.watch("./src", RecursiveMode::Recursive).unwrap();
    
    for event in rx {
        Command::new("cargo").arg("test").status().unwrap();
    }
}

Architecture decisions: debounce strategy to batch events within a window, glob filters to ignore noise, and whether to run all tests or only affected ones by path.

Can I also make it watch for config file changes and restart a dev server?
14:17:01

Yes — the cleanest pattern is a watch manifest with per-target configuration. Define each target with a glob pattern, command, and debounce window:

  • test target: src/**/*.rs → cargo test (500ms debounce)
  • server target: config/**/*.yaml → kill -HUP $(pgrep server) (200ms debounce)

This is how cargo-watch and watchexec work. You'd be building a focused, opinionated alternative — ideal Rust learning project.
