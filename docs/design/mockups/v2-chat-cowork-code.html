I want to build a command-line tool in Rust that watches a directory and runs tests when files change. What's the best approach?
2:15 PM

Great choice — you'll want the notify crate for filesystem events. Here's the architecture:

rust · main.rs
use notify::{Watcher, RecursiveMode, watcher};
use std::process::Command;

fn main() {
    let (tx, rx) = std::sync::mpsc::channel();
    let mut watcher = watcher(tx, Duration::from_secs(1)).unwrap();
    watcher.watch("./src", RecursiveMode::Recursive).unwrap();
    
    for event in rx {
        Command::new("cargo").arg("test").status().unwrap();
    }
}

Key decisions: debounce strategy (batch events within a window), glob filters to ignore .git and target/, and whether to run all tests or only affected ones.

2:15 PM
Can I also make it watch for config file changes and restart a dev server?
2:17 PM

Absolutely. The cleanest approach is a watch manifest with per-target configuration:

  • Each target defines a glob pattern + command
  • Files matching the pattern → execute the associated command
  • Support per-target debounce windows (tests: 500ms, server: 200ms)

This is how cargo-watch and watchexec work. You'd be building a focused, opinionated alternative — a great Rust learning project.
